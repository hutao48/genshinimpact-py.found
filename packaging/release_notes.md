### 本版修复：游戏里有其它声音时，“每个音的时长”过于敏感

环境底噪（风声、水声）、短促音效、背景音乐会让时长表把一个音切成好几行、误报“松键/截止”或“同键重按”。本版：

- 开新音、判定同键重按时，要求**这个键自己的频点**像真实按键那样上升并持续（短促音效 130 ms 内就落回原电平；仍在响的余音不会上升；宽带噪音会把所有频点一起抬高、本音并不突出）；
- 已在响的音只由精确音高维持，背景音乐里的半音不再把它“撑”长；
- 判“松键/截止”时排除随后回升的干涉凹陷，电平起伏大时要求更深、更急的跌落。

带真值的噪音基准（5 组演奏 × 5 种噪音，960 个音；`python benchmark_timing.py --noise --old`）：

| 指标 | 1.0.0 | 1.0.1 |
|---|---|---|
| 被切成碎片的行 | 307 | 66 |
| 误报“松键/截止 / 同键重按” | 248 | 81 |
| 噪音被当成按键的多余行 | 326 | 232 |
| 有真值的时长平均误差 | 44.5 ms | 22.0 ms |
| 音符召回率 | 0.890 | 0.889 |

无噪音时同样更干净（碎片 49 → 8，误报截止 49 → 18，时长误差 13.8 → 5.3 ms）；BPM、起音时间不受影响。

另：命令行离线分析（`--analyze 录音.wav`）报告的 BPM 改取演奏期间最后一个高置信度读数，录音结尾只剩环境声/音效时不再被带偏（例：结尾只剩噪音的录音 305.7 → 142.8，真值 142.9）。

### 1.0.0 的主要内容

- 时间戳改为音频样本时钟；约 5 ms 分辨率定位敲击瞬间；按每个音自身的电平轨迹定位结束，同一键连按逐个拆开；
- BPM：和弦合并为一次起音，软核周期打分 + 分段回归精修；
- 时长表“间隔(ms)”列与结束方式备注；命令行 `--analyze 录音.wav` 离线分析。
